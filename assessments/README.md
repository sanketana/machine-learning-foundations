# Assessments

Assessment in this course is applied, not quiz-shaped: the student is always
asked to *do the thing* on a fresh small dataset, then reason about the
result. Details follow HANDOFF.md §9.4.

## Components

| Artifact | When | Purpose |
|---|---|---|
| `prerequisite-check.ipynb` | Before enrollment | ~30-min diagnostic: Python control flow, functions, pandas filtering/groupby, one matplotlib plot. Defines the enrollment bar (Grade 8/9+, intermediate Python). Includes a scoring guide. |
| `module-checkpoints/checkpoint-module-{1–5}.ipynb` | After each of Modules 1–5 | ~30-min applied check mirroring the module's skills on a fresh dataset. Each has a solutions notebook for the teacher. |
| `capstone/` | Sessions 22–24 | The capstone brief, curated dataset options, the 3-question Project Ethics Check template, and the Demo Day rubric. |

## Rubric conventions

Every checkpoint and the capstone are scored on three dimensions, equally
weighted unless a rubric says otherwise:

1. **Concept understanding** — can the student explain *why*, not just run
   code?
2. **Execution** — does the notebook run, is the workflow complete, are the
   results correct?
3. **Reasoning quality** — are claims backed by named metrics ("numbers, not
   vibes"), are limitations acknowledged, is the interpretation sound?

For the capstone, reasoning and communication are weighted at least as
heavily as model accuracy: a mediocre model excellently reasoned about beats
a great model the student can't explain.
